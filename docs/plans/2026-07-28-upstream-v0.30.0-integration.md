## 5. 追随実装が必要な破壊的変更

### 5.1 CEL 型変更 — 既存機能が壊れる

`created_ts` / `updated_ts` が `IntType` → **`TimestampType`**、
`now()` 関数 → **`now` 変数**。

- upstream 自身は `useMemoFilters.ts` の `displayTime` を
  `created_ts >= timestamp(N)` に修正済み。
- fork が追加した `displayMonth` 分 (`web/src/hooks/useMemoFilters.ts`) は
  型エラーになる。**決定 2 により、この分は移植せず upstream 仕様へ戻す。**
- `internal/filter/schema.go` の `envOptions` に fork が追加した
  `cel.Variable("has_image_attachment", cel.BoolType)` は、削除された
  `nowFunction` の直前行なので確実に衝突する。解決自体は 1 行の位置調整。

### 5.2 filter エンジン内部 API 変更

- `ContainsCondition` → `TextMatchCondition` / `RegexCondition` に分割
- `FieldAccessorValue` 追加、`render.go` に +244 行
- `size()` が string 列にも対応、`FieldKindVirtualAlias` 解決を追加

fork の `FieldKindExistsSubquery` (= `attachment.hasImage`) は additive なので
**そのまま残せる**。ただし `renderCondition` / `renderComparison` の switch 位置が
動くため手作業マージになる。

### 5.3 エディタ全面書き換え — 最大の作業量

textarea ベース → **CodeMirror ベースの WYSIWYG (raw モードトグル付き)**。

upstream で削除された fork 依存先:

- `Editor/TagSuggestions.tsx` (fork が `isHiddenLegacyTag` フィルタを 2 行追加)
- `Editor/commands.ts` / `Editor/shortcuts.ts` / `Editor/SlashCommands.tsx` /
  `Editor/SuggestionsPopup.tsx` / `Editor/useSuggestions.ts` /
  `Editor/useListCompletion.ts`
- `hooks/useDragAndDrop.ts` / `hooks/useKeyboard.ts`
- `components/EditorToolbar.tsx` (→ `Toolbar/EditorToolbar.tsx` へ移動)

upstream の新構造:

- `Editor/{controller,extensions,formatting,tagAutocomplete,theme,...}.ts`
- `EditorContent.tsx` は CodeMirror ホストのみ。paste / drop は CodeMirror 内部に
  集約され、外部インタフェースは `onFiles(files: File[])` 1 本
- `EditorRefActions` → **`EditorController`** 型契約へ変更
- `types/insert-menu.ts` → `types/insertMenu.ts` にリネーム

決定 3 に基づく移植方針 (外付け維持):

1. `TagSection` / `DiaryDateControl` は `MemoEditor/index.tsx` から
   `<EditorContent>` の外側に再マウントする
2. 一括画像アップロード安定化 (`createLocalFiles` による逐次読み込み) を
   upstream の `onFiles` へ再接続する
3. `state.tags` / `SET_TAGS` と `serializeTagContent` /
   `extractBoundaryTagLines` の往復は維持する
   (upstream が `state/` を −100 行規模で整理しているため手作業)
4. `isHiddenLegacyTag` は `tagAutocomplete.ts` へ移植しない。
   legacy タグ隠蔽は `TagSection` と読み側 `MemoBody` に留める

### 5.4 `MemoView/components/MemoBody.tsx`

upstream が本文＋添付を `ClampedSection` で包む構造に書き換え、
`getContentRevision` (fork が `key` に使用) を削除。
fork の 4 箇所 — `extractBoundaryTagLines` による本文 / タグ分離、可視タグチップ描画、
`InlineImageGrid`、`splitVisualAttachments` — を新構造へ再配置する。

`InlineImageGrid` の依存先はすべて `v0.30.0` に存在する
(`MemoMetadata/Attachment/attachmentVisualClasses.ts`、`MotionPhotoPreview.tsx`、
`MemoContent/Tag.tsx`、`utils/media-item.ts`)。

### 5.5 UI ライブラリ移行 Radix → `@base-ui/react`

`asChild` → `render` prop に変更。

fork 追加コンポーネント (`TagSection` / `DiaryDateControl` / `InlineImageGrid`) は
素の要素 + `cn` のみで、影響は軽微。fork が変更した web ファイルのうち
`asChild` を含むのは `MonthNavigator.tsx` だけで、これは決定 2 により
upstream 版へ戻すため追加作業は発生しない。

### 5.6 フロントエンドツールチェーン

- TypeScript `^6` → **`^7`**
- `@emotion/*` 削除、`textarea-caret` 削除、Radix 個別パッケージ削除
- CodeMirror / Lezer 追加、`@base-ui/react` 追加
- `pnpm-lock.yaml` 全面更新

fork の `web/tests/` 7 ファイルと `pnpm lint` が TS7 で通るかは実測が必要。

### 5.7 DB マイグレーション (決定 1 で受け入れ済み)

`store/migration/{sqlite,mysql,postgres}/0.30/00__user_tag_setting.sql`
`system_setting` の `TAGS` を各ユーザーの `user_setting` へコピーする。
`proto/store/user_setting.proto` に `TAGS = 8` /
`TagsUserSetting` / `UserTagMetadata` (色・blur) が追加される。

**デプロイ前に `docs/diary-mode-operations.md` の手順でバックアップを取得する。**

### 5.8 API 破壊的変更

fork が直接使っていなければ upstream フロント側で完結する。

- `GetMemoByShare` → `GetSharedMemo`、
  `/api/v1/shares/{share_id}` → `/api/v1/shares/{share_token}/memo`
- `ListMemoComments` / `ListMemoReactions` から `total_size` 削除
- user_service のリソース ID を AIP 準拠へ、`ListUsers` ページネーション実装
- `CreateMemoRequest.memo_id` に書式制約
  (`^[a-zA-Z0-9]([a-zA-Z0-9-]{0,34}[a-zA-Z0-9])?$`)

## 7. バックエンド側の見通し

fork のバックエンド介入点は 3 箇所で、いずれも `v0.30.0` に同じ形で残っている。

1. `attachment_service.go` の `CreateAttachment` 内、EXIF strip の直前
   (`maybeConvertRawImageAttachment`) と直後 (`maybeOptimizeImageAttachment`)。
   upstream は EXIF ヘルパを `attachment_service_image.go` へ分離したが、
   呼び出し位置は不変
2. `v1.go` の `imageProcessingSemaphore: semaphore.NewWeighted(2)` 行。構造は同一
3. `attachment_motion.go` は upstream で 1 バイトも変わっていない (blob 同一)。
   fork の `isAndroidMotionContainer` → `IsAndroidMotionContainer` 公開化は
   自動的に保持される。マージ後に新規 upstream ファイル側へ小文字の呼び出しが
   増えていないかだけ再確認する (調査時点では存在しない)

重いのはフロントエンド、特にエディタ。

## 8. スライス分割

一括マージ後に一括解決するのは現実的でないため、
`git merge --no-commit` を 1 回走らせた上で、領域ごとに handoff を分ける。

| Slice | 内容 | 独立検証 |
| --- | --- | --- |
| 0 | `.\scripts\prepare-upstream-update.ps1 -Tag v0.30.0` を実行し、実際の衝突を確定する | 衝突ファイル一覧 |
| 1 | backend + `internal/filter` (CEL 型変更追随、`has_image_attachment` 復元、`cmd/memos/main.go`) | `docker build --platform linux/arm64` / CI Go test |
| 2 | エディタ移植 (決定 3: 外付け維持。`TagSection` / `DiaryDateControl` 再マウント、`onFiles` へ逐次アップロード再接続、`state.tags` 復元) | `pnpm test` + 実機確認 |
| 3 | `MemoBody` / `InlineImageGrid` 再配置。`displayMonth` 関連は決定 2 に従い upstream 版へ戻す | `pnpm test` |
| 4 | i18n マージ、ワークフロー (削除維持)、`.upstream-version` 更新、docs 更新 | `pnpm lint` |
| 5 | `pnpm release` + Docker arm64 ビルド。バックアップ取得後に 0.30 マイグレーション適用 | 実機スモーク |
| 6 (後続) | `displayMonth` を CEL 時刻アクセサで再構築 | `pnpm test` + 実機確認 |

Slice 2 が単独で最大。ここを分割せずに進めると途中で止まる。

## 9. 検証と制約

- Go はローカル未導入。バックエンド検証は
  `docker build --platform linux/arm64 -f scripts/Dockerfile .` または CI
- フロントエンドは `web/` から `pnpm install --frozen-lockfile` →
  `pnpm lint` → `pnpm test`。生成物が対象のときのみ `pnpm release`
- commit / push / image 公開 / deploy は明示依頼があるまで実行しない
- LF 改行と `.gitattributes` を維持する
- `AGENTS.md` / `CLAUDE.md` は ignored のまま。ステージしない

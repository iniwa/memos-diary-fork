# upstream v0.31.0 integration

Status: Source integration and review complete; schema/API changes accepted in Decision 0006. Delivery in progress.
Baseline: v0.30.0; target: v0.31.0 (`2b2192d`).

The user requested merging and progressing as far as possible through deployment on
2026-09-25. This authorizes the integration work and established delivery target;
protected schema/data acceptance was subsequently given; see Decision 0006.

## Compatibility and preserved behavior

- Preserve boundary tag editing, draft persistence, hidden legacy photo tags, the
  inline image grid, RAW conversion, image optimization, sequential uploads, image
  filtering, calendar date prefill, and local-month timestamp boundaries.
- Port the image pipeline to `server/api/v1`, filtering to `filter`, and frontend
  build artifacts to `server/frontend/dist`; keep the existing API route prefixes.
- Accept upstream UI structure, including Spaces, Views and the full calendar;
  retain the diary year picker and month filtering in the sidebar.
- Keep removed upstream release/canary/stale workflows removed. Preserve existing
  GHCR/Portainer target, ports, volumes, and environment flag defaults.
- Schema/proto files are upstream-owned and must match the tag exactly; no fork
  migration additions, edits, or reordering.

## Data changes requiring acceptance before application

SQLite has seven new migration files: Shortcuts to Views; named storage settings;
reaction references to memo IDs (orphan reactions are discarded); Spaces with a
memo-table rebuild; membership status; Space payload; canonical unique email with
a user-table rebuild (invalid/duplicate email values are cleared). MySQL/Postgres
also include case-sensitive username migration. All three latest-schema files change.

API changes include removal of ShortcutService in favor of user Views; removal of
reaction contentId; new Spaces/invitations/membership and upload operations;
attachment media metadata, named storage and instance access mode; account settings,
notifications and usage/export/import contracts. Generated bindings/OpenAPI change
with these definitions. RSS is removed. Active administrators can individually
read/manage private and Space-only memos; collection filtering still applies.

Before production writes: verify applicable migration checks, take a consistent
backup of the database/assets/thumbnail cache, retain the old image identity, and
keep rollback tied to the pre-upgrade data backup. Image-only downgrade is not a
safe rollback. Existing restore procedure has not been fully verified.

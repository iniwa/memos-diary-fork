## Release notes: confirmed impact to evaluate

### 26.10.0

The release notes describe a default rich editor with account-level Markdown mode; new Views and attachment filters including `has_image`; per-user usage limits replacing two instance caps without carrying their old values; declarative configuration under `/etc/memos/config`; administrator-only streamed export replacing member export; password-bound access tokens; and a broad breaking API revision. REST paths change from `/api/v1/...` to `/api/...`, Connect/gRPC package paths lose `.v1`, resource types change, many messages/fields are renamed, protobuf field/enum numbers are renumbered, and `UserService.ExportMemos` is removed. The notes also say `/etc/secrets/memos-idp-*.json` and `memos-instance-setting-*.json` are no longer read; preserve identity-provider UIDs when moving configuration and preview with `memos config plan` before startup. These are release-note findings only; exact fork compatibility and data/config effects remain unverified.

The 26.10 notes further state that databases older than `0.31.0` must pass through `0.31.0`, while `0.31.0` upgrades directly. Current deployment is based on v0.31.0, but this is not a substitute for migration-file comparison or validation against the actual schema baseline.

### 26.11.0

Release notes confirm Safari Japanese/Korean composition handling, JSON/logged attachment-read failures and 404 for missing local files, cache entry-count/concurrent-expiry fixes, and a startup warning for old `/etc/secrets` configuration filenames. The release explicitly references moving configuration into `/etc/memos/config`. No migration or proto changes are described in these notes; **absence from release notes is not evidence that those directories have zero changes**.

## Schema and API file inventory

Do not use Decision 0006: its approval is restricted to v0.31.0. Full path lists and canonical per-path comparison links are appended below. The target contains one new incremental schema change, described after the list.

The tree comparison reports 137 migration paths: 4 added, 130 deleted, and 3 modified. The added paths are `store/migration/README.md` and one `26.10/00__add_creator_indexes.sql` per dialect; the three modified paths are dialect `LATEST.sql`. The target deletes historical migration scripts from the shipped source tree. The new migration adds `idx_attachment_creator_id` on `attachment(creator_id)` in SQLite/MySQL/PostgreSQL and `idx_memo_creator_id` on `memo(creator_id)` in MySQL/PostgreSQL (SQLite already has the memo index). This adds indexes and does not transform or delete row values. MySQL statements do not use `IF NOT EXISTS`; rerun/idempotence behavior must be checked through the migrator, not assumed. The upstream migration README sets the fixed minimum schema baseline at `0.31.8` (v0.31.0), says historical SemVer scripts are retained in history/released binaries but no longer embedded in the current binary, and requires old schemas to pass through the supported baseline. Thus source deletion of historical scripts is paired with the baseline gate; confirm startup/migrator behavior in the scoped code review and tests before approval. `LATEST.sql` changes add these creator indexes for fresh installs. Exact file lists and links follow below.

The 26.10 notes and `proto/api/CHANGELOG.md` establish the breaking API contract: `/api/v1/*` and `/memos.api.v1.*` routes/packages are removed (26.10 temporarily returns 410); JSON field names are mostly preserved, but protobuf field numbers and enum numeric values are renumbered and binary clients must regenerate. Service/request/response/resource names and fields change, including MemoService parent names and comment response; user stats; personal access token and linked identity timestamps/names; import models; notification invitation state; setting request/response wrappers; auth expiry and SSO fields. `UserService.ExportMemos` is removed and export moves to a serialized administrator-only streaming file download; import remains. Old upload-size and memo-length settings are removed without migrating values and replaced by whole-list `USAGE_LIMITS`, with `RESOURCE_EXHAUSTED/QUOTA_EXCEEDED`. Password changes invalidate access tokens and revoke other refresh sessions. `/etc/secrets` deployment JSON files stop applying; declarative configuration under `/etc/memos/config` manages IDPs, instance settings, bootstrap users, and linked identities. Preserve IDP UID and plan before applying. Config-managed fields reject API writes; S3 setting validation also tightens. Exact affected source and generated files are linked in the full list below. The fork's Go server and web client consume generated/API definitions, so their matching changes and external clients must be reviewed/regenerated together.

The target tree has 100 changed paths under `proto/`: 46 added, 43 deleted, and 11 modified. They comprise API source definitions/docs, store source definitions, generated Go/Connect/gRPC/gateway/OpenAPI, generated store bindings, and generation configuration. A further 19 generated TypeScript API bindings changed under `web/src/types/proto/api/` (10 added, 9 deleted). The source API moved from `proto/api/v1` to `proto/api`; store source changes include `InstanceSetting` usage limits/configuration state and updates to attachment, memo, and user-setting fields. These protobuf changes are a wire-compatibility break because field numbers/enums change; regenerate and rebuild server and web client together, update REST/gRPC/Connect route consumers, and run proto lint, Go checks, frontend checks, and API compatibility checks. The exact file lists follow below.
